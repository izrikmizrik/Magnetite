## Решения владельца
- Ядро — из main; ПК-сборку не менять.
- Шейдер-API на мобилах — обязательно последней версии (из main).
- Вход везде как в iOS: Microsoft device code + Ely.by, прямо в игре.
- Тач-управление на мобилах настраивается как в iOS.
- Файлы игры на телефоне (2026-11-22): скачивание с открытых серверов Mojang разрешено после входа и Microsoft,
  и Ely.by (решение владельца; как фактически делает iOS-форк). Офлайн-режим — на уже скачанных файлах.
- Ввод текста на этапе 1 (логин/пароль Ely.by, офлайн-имя): своя тап-клавиатура в игре на основе OSK main;
  системная клавиатура (IME) — на этапе 4.
- Таблицы для телефонов (данные, которые подготовка main получает из кода Minecraft через Java: реестры, рецепты,
  ворлдген; без файлов Mojang) публикуются релизами в **отдельном публичном репозитории** `magnetite-tables`,
  не в Magnetite: если их попросят убрать, основной проект не затронут. Телефон качает их после входа
  (установщик — `crates/horizon-client/src/game_files.rs`, адрес и sha256 — `MAGNETITE_TABLES_URL` /
  `MAGNETITE_TABLES_SHA256`; сборка без них не предлагает скачивание).
- Microsoft client ID: только **своё** Azure-приложение Magnetite + одобрение Mojang (App ID review,
  https://aka.ms/mce-reviewappid). ID Horizon запрещён его docs/forking.md («Microsoft sign-in in a fork»),
  чужие ID (Cazza из iOS-форка, официального лаунчера) — тоже (docs/microsoft-account.md). ID — переменная
  репозитория `MAGNETITE_MSA_CLIENT_ID` (не секрет). До одобрения на телефонах работают Ely.by и офлайн.
  **Временно (решение владельца, 2026-11-22):** переменная выставлена на client ID Cazza Launcher из iOS-форка,
  пока владелец не получит свой; риск — экран согласия «Cazza Launcher» и отзыв ID. Замена — смена переменной.
- Предустановленные нативные моды на мобилах: из 60 модов iOS-форка (`NATIVE_MODS.md`) оставить только
  `coords_hud` (координаты), `fps_overlay` (FPS) и мод урожая по клику (`right_click_crops`, выбран). Остальные не вшивать. На мобилах моды вшиваются в бинарник статически
  (как в iOS-форке): загрузка `.dll`/`.so` и процесс-холдер (`runtime-process`, `holder`) — только ПК, фича `native-mods`.

## Площадка модов на мобилах
- Экран «Моды» в игре (на мобилах нет лаунчера), тот же реестр Horizon (`horizon-mod-package` с `index`), что у ПК-лаунчера.
- WASM-моды: скачал — работает (iOS через Pulley, без JIT).
- Нативные моды: на ПК лаунчер собирает их из исходников; на телефоне компилировать нельзя → готовые сборки
  от нашего CI под `aarch64-linux-android` и `aarch64-apple-ios`.
  - Android: `.so` в папке приложения, `dlopen`.
  - iOS — по ТЗ (требование 3: JIT на iOS — принятая зависимость). **С JIT** (StikJIT и т.п.): нативные `.dylib`
    грузятся напрямую, WASM — Cranelift в машинный код, LuaJIT — с JIT. **Без JIT** игра не падает: WASM — Pulley,
    Lua — `jit.off()`; нативные моды недоступны или, как запасной путь, переподписываются в приложении тем же
    сертификатом через `ferrite-signer` (подход LiveContainer).
  - Механизма «внешняя библиотека модов через JIT» в iOS-форке нет (моды вшиты при сборке): строим по ТЗ с нуля.
- **Сборочная ферма модов** (на телефоне компилировать нельзя: на iOS запрещено запускать `rustc`, на Android —
  ~1 ГБ тулчейна и минуты на мод). Релизный workflow Magnetite тем же `rustc` собирает моды реестра под
  `aarch64-linux-android` (NDK) и `aarch64-apple-ios` (macOS-раннер) и выкладывает в релизы репозитория
  `magnetite-mods` по версии игры и платформе (нативные моды привязаны к `GAME_BUILD_ID` и версии `rustc`).
  Собирать только моды, чья лицензия разрешает раздачу бинарников (MIT, GPL со ссылкой на исходники, CC-BY-NC-SA
  некоммерчески); без лицензии — не собирать. В `cargo-horizon-mod` — `--target android/ios` для авторов.
- **WASM — основной путь для новых модов**: один `.wasm` на все платформы, без сборок под каждую (на iOS — Pulley).
- **iOS: JIT — основной режим для портов владельца** (тяжёлые моды: Create, Farmer's Delight; Pulley в разы медленнее).
  Игра при старте проверяет JIT (пробное выделение исполняемой памяти). Поле манифеста мода, например
  `ios_jit = "required" | "recommended" | "optional"`: без JIT `required`-мод не включается и игра объясняет, как
  включить JIT (StikJIT и т.п.), остальные идут через интерпретатор; игра не падает (требование 3 ТЗ). Площадка
  модов на iOS помечает моды, которым нужен JIT.
- **iOS: компиляция WASM в процессе игры.** На ПК wasmtime компилирует моды в дочернем процессе (игра перезапускает
  себя как компилятор, `horizon_mod_host::exit_if_compile_child`). На iOS процессы запускать нельзя — нужен путь
  компиляции внутри процесса (вместе с выбором цели: нативный код при JIT, `pulley64` без JIT).
- Ограничения WASM (docs/modding): нет нативного пути (`[[native.*]]`, миксины), прямого GPU, своих генераторов чанков,
  файловой системы, потоков. Create — симуляция в Rust-ядре (шаг 8 ТЗ), контент — WASM/Lua.
- **Расширение WASM (после шагов 1–7 ТЗ)**, через тот же каталог API (WASM и Lua получают всё сразу), по порядку:
  1. генераторы чанков и источники биомов — пачками (чанк / 4×4×4 квартов за вызов) + канонизация NaN в wasmtime,
     чтобы мир был бит-в-бит одинаков на Cranelift и Pulley (требование 2 ТЗ);
  2. своя папка мода (`config/<mod>/`, только внутри неё);
  3. параллельные вызовы мода на рабочих потоках (по экземпляру на поток; сами wasm-потоки остаются выключены);
  4. безопасное шейдерное API (WGSL + описание прохода, проверяет игра; не сырой wgpu).
  Миксины/нативный путь WASM не получит принципиально — вместо них больше `[[inject]]`-точек.
  Цена: расхождение с апстримом Horizon растёт.
- Фича `native-mods` вырезает с мобил только ПК-механику (сборка лаунчером, процесс-холдер `holder`/`runtime-process`);
  мобильный загрузчик готовых библиотек — отдельно.

## На потом
- **e4mc (порт на Rust) для кооператива.** Встроить во все три: ПК, Android и iOS (решение владельца изменено: iOS тоже). Владелец: «работает хорошо».
  Исходники: https://github.com/izrikmizrik/e4mc-for-rust (порт владельца, MIT, свой код; крейт `e4mc-tunnel`,
  QUIC к брокеру `broker.e4mc.link`, есть `--custom-relay` и `--broker-url`). Сейчас это отдельный бинарник рядом
  с LAN-миром; для Magnetite превратить в библиотеку под фичей `e4mc` и кнопку в игре («Открыть через e4mc»),
  которая сама берёт порт LAN-мира. На iOS отдельный процесс запустить нельзя, поэтому только библиотекой.
  В настройках — свой relay/брокер (на случай, если e4mc закроет свои серверы для неофициальных клиентов).
  **Два отдельных релиза из одного коммита:** «Magnetite X.Y.Z» (тег `vX.Y.Z`: ПК, Android, iOS) и
  «Magnetite X.Y.Z (e4mc)» (тег `e4mc-vX.Y.Z`: ПК, Android и iOS с фичей `e4mc`). Префикс, а не
  суффикс `-e4mc`: по semver дефис означает предрелиз. «Latest» на GitHub — обычный релиз; на e4mc — постоянная
  ссылка в README. Апдейтер в приложении следит только за своим каналом (`v*` или `e4mc-v*`). На Android разные
  ID приложения (например `dev.magnetite` и `dev.magnetite.e4mc`), чтобы обе версии ставились рядом; на iOS так же разные bundle ID.
  **Лицензия:** порт под MIT, копирайт владельца — встраивать можно, уведомление MIT сохранить. Не нарушать правила
  relay-серверов e4mc (честный клиент, без нагрузки); по возможности предупредить авторов. Риск: relay принадлежит им и может быть закрыт для неофициальных клиентов —
  e4mc остаётся опциональным, при открытой серверной части дать настройку своего relay.

## Организация репозитория
- Один публичный репозиторий `magnetite`, одна ветка `main`, платформы — папками: общее ядро в `crates/`,
  новые крейты `magnetite-android`, `magnetite-ios`, упаковка в `packaging/{android,ios}`, ПК-лаунчер в `launcher/`.
  Ветки — только под задачи. Внутренние крейты `horizon-*` не переименовывать.
- Продукты: Magnetite, Magnetite Android, Magnetite iOS. Лицензия LGPL-3.0-or-later (MIT-код форков с уведомлением).
- CI: свои workflow (ПК, Android, iOS на macos-latest) вместо 28 workflow апстрима.
