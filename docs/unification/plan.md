# План сведения Horizon (main как единое ядро)

## Сейчас
1. Урезание мобильной сборки фичами (`desktop` в default, `mobile` для телефонов): `mobile-trim-plan.md`.
2. Шаги ТЗ по порядку из ТЗ: `step0-core-map.md` — разведка готова.
3. Перенос платформенных слоёв iOS и Android на main, вход и тач-редактор «как в iOS»: `fork-feature-map.md`.

## Решения владельца
- Ядро — из main; ПК-сборку не менять.
- Шейдер-API на мобилах — обязательно последней версии (из main).
- Вход везде как в iOS: Microsoft device code + Ely.by, прямо в игре.
- Тач-управление на мобилах настраивается как в iOS.
- Предустановленные нативные моды на мобилах: из 60 модов iOS-форка (`NATIVE_MODS.md`) оставить только
  `coords_hud` (координаты), `fps_overlay` (FPS) и мод урожая по клику (`right_click_crops`, выбран). Остальные не вшивать. На мобилах моды вшиваются в бинарник статически
  (как в iOS-форке): загрузка `.dll`/`.so` и процесс-холдер (`runtime-process`, `holder`) — только ПК, фича `native-mods`.

## Площадка модов на мобилах
- Экран «Моды» в игре (на мобилах нет лаунчера), тот же реестр Horizon (`horizon-mod-package` с `index`), что у ПК-лаунчера.
- WASM-моды: скачал — работает (iOS через Pulley, без JIT).
- Нативные моды: на ПК лаунчер собирает их из исходников; на телефоне компилировать нельзя → готовые сборки
  от нашего CI под `aarch64-linux-android` и `aarch64-apple-ios`.
  - Android: `.so` в папке приложения, `dlopen`.
  - iOS — по ТЗ (требование 3: JIT на iOS — принятая зависимость). **С JIT** (StikJIT и т.п.): нативные `.dylib`
    грузятся напрямую, WASM — Cranelift в машинный код, LuaJIT — с JIT. **Без JIT** игра не падает: WASM — Pulley,
    Lua — `jit.off()`; нативные моды недоступны или, как запасной путь, переподписываются в приложении тем же
    сертификатом через `ferrite-signer` (подход LiveContainer).
  - Механизма «внешняя библиотека модов через JIT» в iOS-форке нет (моды вшиты при сборке): строим по ТЗ с нуля.
- Фича `native-mods` вырезает с мобил только ПК-механику (сборка лаунчером, процесс-холдер `holder`/`runtime-process`);
  мобильный загрузчик готовых библиотек — отдельно.

## На потом
- **e4mc (порт на Rust) для кооператива.** Встроить во все три: ПК, Android и iOS (решение владельца изменено: iOS тоже). Владелец: «работает хорошо».
  Исходники: https://github.com/izrikmizrik/e4mc-for-rust (порт владельца, MIT, свой код; крейт `e4mc-tunnel`,
  QUIC к брокеру `broker.e4mc.link`, есть `--custom-relay` и `--broker-url`). Сейчас это отдельный бинарник рядом
  с LAN-миром; для Magnetite превратить в библиотеку под фичей `e4mc` и кнопку в игре («Открыть через e4mc»),
  которая сама берёт порт LAN-мира. На iOS отдельный процесс запустить нельзя, поэтому только библиотекой.
  В настройках — свой relay/брокер (на случай, если e4mc закроет свои серверы для неофициальных клиентов).
  **Два отдельных релиза из одного коммита:** «Magnetite X.Y.Z» (тег `vX.Y.Z`: ПК, Android, iOS) и
  «Magnetite X.Y.Z (e4mc)» (тег `e4mc-vX.Y.Z`: ПК, Android и iOS с фичей `e4mc`). Префикс, а не
  суффикс `-e4mc`: по semver дефис означает предрелиз. «Latest» на GitHub — обычный релиз; на e4mc — постоянная
  ссылка в README. Апдейтер в приложении следит только за своим каналом (`v*` или `e4mc-v*`). На Android разные
  ID приложения (например `dev.magnetite` и `dev.magnetite.e4mc`), чтобы обе версии ставились рядом; на iOS так же разные bundle ID.
  **Лицензия:** порт под MIT, копирайт владельца — встраивать можно, уведомление MIT сохранить. Не нарушать правила
  relay-серверов e4mc (честный клиент, без нагрузки); по возможности предупредить авторов. Риск: relay принадлежит им и может быть закрыт для неофициальных клиентов —
  e4mc остаётся опциональным, при открытой серверной части дать настройку своего relay.

## Организация репозитория
- Один публичный репозиторий `magnetite`, одна ветка `main`, платформы — папками: общее ядро в `crates/`,
  новые крейты `magnetite-android`, `magnetite-ios`, упаковка в `packaging/{android,ios}`, ПК-лаунчер в `launcher/`.
  Ветки — только под задачи. Внутренние крейты `horizon-*` не переименовывать.
- Продукты: Magnetite, Magnetite Android, Magnetite iOS. Лицензия LGPL-3.0-or-later (MIT-код форков с уведомлением).
- CI: свои workflow (ПК, Android, iOS на macos-latest) вместо 28 workflow апстрима.
